# DoF Anime の作り方

[English](how-it-works.en.md) ｜ [README](../README.md)

DoF Anime は、AI で作ったアニメ動画（完成済みの RGB 動画）に、あとから被写界深度（ピントの外のぼけ）を付ける After Effects のエフェクトです。
この文書は「どう作ってあるか」と「一から作るときの手順」をまとめたものです。

---

## 1. 全体の流れ

```
素材レイヤーに DoF Anime を付ける
  │
  ├─ 深度を作る（1 回だけ。結果は cache/ に残る。Relight Anime と共有）
  │    AE に素材のフレームを描かせる → relight_depth.exe（ONNX Runtime + CUDA）で深度を推定
  │    → 16bit の深度 PNG を読み込み、非表示のレイヤー「DoF depth」として結線する
  │
  ├─ （任意）キャラのマスクを作る（Auto Subject / Generate Subject、Sharp by Text / Blur by Text）
  │    SAM 3.1 で見つけて動画全体を追いかけ、縁を元の絵の色から切り抜き直す → 非表示のレイヤーとして結線する
  │
  └─ ぼかす（毎フレーム）
       深度を線画に合わせて引き伸ばし、段差を締め、ピントとの差からぼけの半径を求め、
       手前と奥を分けて集める（scatter-as-gather）。CPU 版と GPU 版（CUDA）が同じ計算の部品（DofCore.h）を使う
```

深度の推定とマスク作りを AE の描画の外（別のプロセス）に出しているのは、AE がフレームを任意の順番で、しかも並列に要求するのに対し、
動画の深度推定とマスクの追跡は前後のフレームをまとめて処理しないと時間方向に安定しないためです。

## 2. 深度

深度は [Relight Anime](https://github.com/yuichi-suzuki-highdrama/relight-anime) と同じ仕組みで作り、設定（`%APPDATA%\SRLM\RelightAnime.ini`）とキャッシュも共有します。
Relight Anime で深度を作った素材なら、作り直さずにすぐ使えます。同じコンポに Relight Anime の深度レイヤーがあれば、それを使い回します。

- **モデル**: Video Depth Anything Small（Apache-2.0）。前後のフレームをまとめて見る動画用の深度モデルです。
  推定・正規化・時間方向のならしの詳細は Relight Anime の [作り方](https://github.com/yuichi-suzuki-highdrama/relight-anime/blob/main/docs/how-it-works.ja.md) を見てください。
- **細かさ**（`depth_input_size`）: モデルに入れる短辺の大きさです。既定の 518 では、細い髪の束が深度に入らず、ぼかしても線のまま残ることがありました。
  770 にすると毛先まで入ります（Small のままなので商用可）。
  1376×768・192 コマで、518 は約 19 秒・VRAM の山 約 11GB、770 は約 32 秒・約 21GB でした（fp32）。モデルを fp16 にすると（中だけ fp16、入口と出口は fp32。値の差は平均 0.0002）、770 は約 12GB、1036 は約 55 秒・約 20GB で動きます。1036 では、770 で途切れていた草の葉の先まで入りました。大きい入力ではエンコーダに 1 コマずつ通します（2 コマずつだと約 25GB）。
- **大きいモデル（Large）** は髪も背景も細かく出ますが、**CC-BY-NC-4.0（非商用）** です。Depth Engine = Remote Quality のときだけ使います。

## 3. ぼかしの計算

### 3.1 ぼけの半径（CoC）

- 推定した深度は視差（距離の逆数）に近い量なので、薄いレンズの式どおり、ピントとの深度の差にぼけの半径を比例させます。
  Blur Size は「深度の差 0.5 のときの半径（1080p でのピクセル数）」です。
- ピントの合う幅（Focus Range、既定 0.06）の外で、0.02 の幅でなめらかに立ち上げます（幅の境目でぼけが急に変わらないように）。
- 半径は符号付きで持ちます（手前 = 負、奥 = 正）。手前と奥は Near Blur / Far Blur で別の倍率を掛けます。Near Blur の既定は 0 です（手前はぼかさない）。

### 3.2 集める（scatter-as-gather）

1. 入力をリニアの明るさにし、1/2・1/4・1/8 の縮小も作ります。
2. 16 画素四方の区画ごとに、その区画に届きうるぼけの最大の半径を求めます（区画の最大 → まわりの区画へ広げる）。
3. 各画素のまわりに、黄金角のらせん（Vogel の円盤）で点を等しい面積ずつ並べます（Quality: 48 / 96 / 192 点）。
   点の円がこの画素に届けば、その点の色を足します。
4. 2 つの層に分けて集めます。
   - **奥とピントの層**: 奥の点の広がりは、この画素のぼけまでに抑えます。ピントの合った物に、ぼけた背景がにじみません。
   - **手前の層**: 手前の点は後ろの物の上に広がります。届いた量から「覆う割合」を求め、奥の層の上に重ねます。
5. 点の間隔が広いときは、縮小した画像からバイリニアで読みます。点の間隔に合わせて段を選ぶので、ぼけの中に点の跡（つぶつぶ）や模様が出ません。
6. 明るい所（Highlights / Highlight Threshold）は、リニアの明るさで重みを大きくして玉ぼけにします。

## 4. 境目をきれいにする工夫

推定した深度は粗く、ぼけの境目が絵の輪郭線から 1〜3 画素ずれます。ずれた分は「くっきりした細い帯」や「ぼけた縁」に見えます。

| 工夫 | 内容 |
|---|---|
| 深度を線画に合わせる | 深度を出力の大きさへ引き伸ばすとき、深度が変わる所だけ、素材の色が近い深度の点を重く見る（joint bilateral upsampling）。境目が線画に沿う |
| Edge Expand | 手前の物の深度を、指定した幅だけ外へ広げる。深度の境目より外にある輪郭線を、手前の物に入れる |
| 段差を締める | まわり（1080p で 8 画素）の深度の幅が大きい所では、各画素を近い方の端（手前か奥）に寄せる。段差の途中の深度が無くなり、境目にピントの合った線が出ない |
| Edge Bias | ぼけている側を、くっきりした側へ指定した幅だけ食い込ませる（まわりで、自分よりはっきり大きいぼけを使う）。帯がぼけに入る |
| Edge Soften | 奥のぼけを縦横のガウスでならし、くっきりした物の縁から内側へ、少しずつ弱めながら入れる。縁がふわっとつながる |

## 5. キャラのマスク

既定ではマスクを使わず、深度だけでぼかします。マスクを使うのは、キャラ全体をそろえてくっきり（またはそろえてぼかし）たいときです。

### 5.1 自動で作る（`tools/subject_mask.py`）

SAM 3.1 は ComfyUI に入っている実装と重みを、ComfyUI を立ち上げずに部品として使います（ComfyUI の Python で動かす）。

1. Focus Point のあるコマで、文字（"anime character" など）でキャラを全員見つける。点を含むキャラを 1 人目にし、3 人まで
2. キャラごとに動画全体を追いかける（SAM 3.1 の動画の追跡）
3. 各コマのマスクを、SAM の細かい段（キャラの周りを 1008 画素に切り出して）で詰め直す。追跡のマスクは粗い解像度から引き伸ばしたもので、縁が波打つため
4. 小さな穴を埋め、小さな切れ端を消す
5. 深度で直す: マスクの中で、まわりより明らかに奥の大きな塊は外し、マスクのすぐ外で、キャラと同じ深さの大きな塊は足す
6. 縁の数画素を、元の絵の色から切り抜き直す（クローズドフォーム・マッティング、pymatting）。薄すぎるアルファは消す
7. RGB の PNG に書く（赤・緑・青 = 1〜3 人目）。DoF Anime は Subject Channel = Multi (RGB) で読み、キャラごとに扱う

### 5.2 マスクの使い方

| 項目 | 作り方 |
|---|---|
| Subject Flatten | 推定した深度はキャラの中でも揺れる（髪の先・脚・フリル）ので、マスクの中の深度をキャラの代表の深度（マスクの中の深度の中央値）に寄せる。キャラの中のぼけのむらが無くなる |
| Subject Inset | マスクを内側へ縮め（既定 12 px）、縁をなだらかにしてから使う。マスクは人物の内側を整えるだけになり、人物の縁は深度だけで決まる。マスクの縁のガタガタや、髪の間の埋まりが出ない |
| Inset のときのピント | 縮めた外側の帯は元の深度のまま残るので、ピントは点のまわりの元の深度で決め、点が乗っているキャラの寄せる先もその深度にする（中央値だと、縁の帯と内側でピントがずれた） |
| Inset のときの段差 | 段差を締める処理にマスクを渡さない（縮めたマスクの縁を人物の境目とみなすと、内側に線が出た） |
| マスクをなめらかに | マスクの値は 3×3 の点（1080p で 3 画素間隔）を 1-2-1 の重みで平均して読む。2 人の境目のガタガタが消える |
| Keep Subject Sharp | ピントに関係なく、マスクの中のぼけを減らす（既定 0%）。全員のマスクに効くので、ピントの外のキャラまでくっきりになる点に注意 |

### 5.3 手直し

- **Sharp Layer / Blur Layer**: 平面にマスクを描いて指定します。Sharp Layer の所はぼけを 0 に、Blur Layer の所は深度を「画面のいちばん奥（5 パーセンタイル）」に置き換えます。
- **Sharp by Text / Blur by Text**: 物の名前を英語で入れると（例: flower, grass）、`tools/prompt_mask.py` が SAM 3.1 でその物を探して動画全体で追いかけ、アルファのマスクを作って結線します。

## 6. レンズらしさ

After Effects の Camera Lens Blur にある項目を、集めるときの重みとして作りました。どれも「点 q の絞り（ぼけの形）が、この画素 p に届くか」の判定を変えるだけです。

| 項目 | 作り方 |
|---|---|
| Shape / Blades | 絞りの形。q から p への向きで、多角形の辺までの距離を掛ける（Polygon は羽根 3〜10 枚） |
| Roundness | 多角形の辺までの距離と円（1）を混ぜる |
| Aspect | 点を置く円を楕円にする（横 × √a、縦 ÷ √a。面積は変えない）。区画の届く範囲もその分広げる |
| Cat Eye | 口径食。q の絞りを、画面の中心から q への向きにずらした円で切る（重なった所だけ届く）。画面の端ほどずれが大きく、玉が欠ける |
| Bubble | 正: 玉の縁を明るくする。重みに `1 + 3b(t⁴ − 1/3)`（t = 中心からの距離 ÷ 半径）を掛ける。負: 中心を明るく縁へなだらかに暗くする（`1 − 2b(1/2 − t²)`、−100% で `2(1 − t²)`）。t⁴ と t² の面積の平均は 1/3 と 1/2 なので、どちらも明るさの合計は変わらない。細い髪の束をぼかすと、正では帯の縁が二重の線に見え、負ではやわらかく溶け合う |
| Fringe | 赤・緑・青で絞りの半径を少しずつ変える（100% で赤 +8%、青 −8%）。重みも色ごとに持ち、玉の縁に色ずれが出る |

## 7. ピント送り

- **Focus Point** の深度は、点のまわり（画面の高さの 1.2% の半径）の深度の中央値です。点がキャラの上にあれば、そのキャラの代表の深度にします。
- **Focus Pull Time**（既定 0.8 秒）: 前後のコマの Focus Point を Hann の窓（なめらかな重み）で平均します。
  映画のフォーカス送りのように、ゆっくり動き始めてゆっくり止まります。停止したキーフレームでパッと切り替えても、この時間で移ります。
- 前後のコマのパラメータを読むので、AE に「他の時刻の入力を使う」ことを知らせています（`PF_OutFlag_WIDE_TIME_INPUT`）。
  知らせないと、Focus Point が変わらないコマで AE が前の結果を使い回し、ピント送りが止まりました。

## 8. AE 標準の Camera Lens Blur との違い

同じ深度・同じピント送り・同じぼけの強さ・同じ絞り（九角形、丸み 70%）で、AE 標準の Camera Lens Blur と比べました。

| 場面 | Camera Lens Blur | DoF Anime |
|---|---|---|
| 背景のぼけ | ほぼ同じ | ほぼ同じ |
| ピントの合ったキャラの手前側（脚・手・フリル） | 深度どおりにぼけ、手はくっきり・すぐ横のフリルはぼける、のようにまだらになる | Focus Range と Subject Flatten で全身くっきり |
| 手前のぼけの縁（髪の束） | 後ろの物の上に広がらず、縁に細い線がくっきり残る | 手前の層を後ろの物の上に重ねるので、なめらかにぼける |
| 速さ（1376×768、192 コマ） | 約 8 秒 | 1 コマ数 ms（GPU） |

## 9. 速さ（CPU 版と GPU 版）

- ぼかしの計算は `plugin/src/DofCore.h` にまとめ、関数はすべて CPU と CUDA（`__host__ __device__`）の両方で動きます。
- 全体の手順は、CPU 版（`DofAE.cpp`、作業スレッドで行ごと）と GPU 版（`DofGPU.cu`）がそれぞれ持ち、同じ関数を呼びます。差は 8bit で最大 1 段です。
- GPU の作業領域は、必要な量を数えてから 1 つの塊で取ります。
- 1376×768 で GPU 約 3〜8 ms（マスクや Quality による）、CPU 約 0.1〜0.3 秒（RTX 5090 / 24 スレッド）。

## 10. AE に組み込むときの注意

| 事柄 | 対応 |
|---|---|
| フレームの順番 | AE は任意の順・並列にフレームを要求する。深度の推定とマスク作りは描画の外（別プロセス）で行う |
| 自動生成 | 補助 AEGP（`DoFAnimeHelper.aex`）のアイドルフックからジョブを進める（Relight Anime と同じ） |
| キャッシュ | 素材のファイル名・場所・大きさ・更新日時から決める。作り直すときは Generate を押す |
| レイヤーの読み方 | 深度・マスク・手直しのレイヤーは、出力の範囲ではなく全体を取り出し、レイヤーの中の位置の割合で合わせる |
| パラメータの追加 | パラメータ ID を固定し、新しい ID は後ろに足す。保存したプロジェクトの値を引き継ぐ |
| GPU | CUDA のときだけ GPU 可と返す。ほか（DirectX など）は CPU 版 |
| コンポビュー | Focus Point に「Focus」の枠を描く。位置のドラッグは AE 標準の 2D ポイントのハンドルに任せる |

## 12. 一から作る手順

必要なもの: Windows 11、After Effects 2024 以降（AE 2026 で確認）、Visual Studio 2022 Build Tools（C++）、CMake、Ninja、CUDA Toolkit 12.8 以降、After Effects SDK。

1. **深度の準備**: Relight Anime の手順どおりに、ONNX モデルと `relight_depth.exe` を用意する（`%APPDATA%\SRLM\RelightAnime.ini` に場所が書かれる）。
   細かく作るなら、fp16 のモデルを作って（`python tools/export_vda_onnx.py --split --fp16`）`encoder` と `head` に指定し、同じファイルに `depth_input_size=1036` を足す（VRAM 24GB 以上）
2. **AE SDK** を https://developer.adobe.com/after-effects/ から入手して展開する（リポジトリには含めていない）
3. **プラグイン**をビルドして入れる（管理者権限。AE を閉じてから）:
   `.\plugin\build.ps1 -SdkRoot <SDK の場所> -Install`
4. （任意）**キャラのマスク**を使うなら、ComfyUI に SAM 3.1 の重み（`models/checkpoints/sam3.1_multiplex_fp16.safetensors`）を入れ、ComfyUI の Python に pymatting を入れる
5. AE で素材のレイヤーに「SRLM > DoF Anime」を付ける。深度ができると自動で結線される

DoF Anime だけ設定を変えたいときは、`%APPDATA%\SRLM\DoFAnime.ini` に同じ形（key=value）で書きます（RelightAnime.ini のあとに読みます）。

## 14. 既知の限界

- 手前の物を大きくぼかすと、本来その裏に見えるはずの背景は元の絵に無いので、まわりの色で埋まる
- 風になびく細い髪の毛先が、深度に入らずに線のまま残ることがある（`depth_input_size` を上げる、Blur by Text で髪を指定する）
- 自動のマスクは、髪の束の間の細い隙間まで埋めることがある（Subject Inset で縁を深度に任せると目立たない）
- 時間伸縮・タイムリマップしたレイヤーには深度とマスクが追従しない
